# C++Builder 2007: совместимость MAX-адаптера

Этот файл фиксирует требования именно фактического toolchain LanMon, проверенного по присланным заголовкам C++Builder 2007.

## Что изменено

Production-код под `__BORLANDC__` больше не использует STL-контейнеры и `std::string`:

- строки API — `AnsiString` (`MAX_TEXT`);
- списки входящих сообщений — `TList`;
- HTTP-заголовки — `TStringList`;
- временные UTF-8/CP1251 буферы — обычные `new[]`/`delete[]`;
- JSON parser хранит массивы и объекты через VCL-совместимые списки.

Portable `std::string/std::vector/std::map` остаются только в ветке `#else` для Linux CI и не компилируются BCB2007.

## Indy из BCB2007

Используются имена классов и generated headers из фактической поставки Builder 2007:

```cpp
#include <InHTTP.hpp>
#include <InSSLOpenSSL.hpp>
#include <InMultipartFormData.hpp>

TInHTTP
TInSSLIOHandlerSocketOpenSSL
TInMultipartFormDataStream
```

Не использовать для этого проекта `IdHTTP.hpp`, `IdSSLOpenSSL.hpp`, `TIdHTTP` и другие имена из более новых версий Indy.

## TLS

В присланном `InSSLOpenSSL.hpp` нет отдельного enum-значения для TLS 1.2. Поэтому transport использует:

```cpp
Ssl->SSLOptions->Method=sslvSSLv23;
```

В старом Indy это negotiation method OpenSSL, а не требование подключаться по SSLv2/SSLv3. Чтобы соединение с MAX прошло, установленный рядом с LanMon OpenSSL runtime должен быть ABI-совместим с этой версией Indy и уметь TLS 1.2. Сервер MAX старые протоколы не принимает.

Проверка сертификата не отключается:

```cpp
Ssl->SSLOptions->RootCertFile=rootCert;
Ssl->SSLOptions->VerifyMode=TInSSLVerifyModeSet()<<sslvrfPeer;
Ssl->SSLOptions->VerifyDepth=9;
```

При отсутствии `certs\\max-ca.pem` transport работает fail-closed и сетевой запрос не выполняет.

## Проверка на машине с BCB2007

После получения ветки сначала выполнить обычную компиляцию всех трёх файлов `Max/api/*.cpp`. Затем собрать LanMon полностью.

После успешной сборки проверить по порядку:

1. `certs\\max-ca.pem` находится рядом с `lanmon4.exe` в подпапке `certs`.
2. Загружаются OpenSSL DLL, соответствующие фактическому Indy BCB2007.
3. `GetMe` возвращает информацию о MAX-боте.
4. Получение сообщений через `GET /updates` работает и marker продвигается.
5. Отправляется обычное текстовое сообщение.
6. Отправляется картинка.
7. Отправляется документ.
8. Русский текст корректно проходит CP1251 → UTF-8 → CP1251.
9. При удалённом или испорченном `max-ca.pem` запрос завершается ошибкой, а не переходит на непроверенный TLS.

## Автоматическая защита от повторной поломки

`tests/test_bcb2007.py` проверяет, что production-путь снова не получил STL, новые `Id*` классы Indy или несовместимый TLS enum. Этот тест запускается вместе с остальным CI через `tests/run.sh`.

Linux CI не заменяет финальную компиляцию `bcc32`: единственная окончательная проверка ABI старого Indy/OpenSSL — сборка и запуск на фактическом компьютере с C++Builder 2007.
